## 2. Contabo จัดการผ่าน API ได้แค่ไหน — **ไม่จบ มี 2 ขั้นที่ต้องกดหน้าเว็บ**

REST API: `https://api.contabo.com/v1` · auth = OAuth2 ต้องใช้ **4 ค่า**
(`client_id` · `client_secret` · `username` = อีเมล API user · `password` = **รหัส API ที่ตั้งแยกใน CCP**
ไม่ใช่รหัสผ่านบัญชี) · มี [terraform provider ทางการ](https://github.com/contabo/terraform-provider-contabo)

| งาน                                                  | ผ่าน API ได้ไหม                                                                                                                                                                         |
| ---------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| สั่งซื้อ / สร้าง instance                            | ✅ `POST /v1/compute/instances`                                                                                                                                                         |
| ติดตั้ง OS ใหม่ (reinstall) · start/stop/restart     | ✅                                                                                                                                                                                      |
| ใส่ SSH key + cloud-init (`user_data`)               | ✅                                                                                                                                                                                      |
| ดูรายการเครื่อง / IP ที่ได้รับ                       | ✅                                                                                                                                                                                      |
| Snapshot                                             | ✅                                                                                                                                                                                      |
| Object storage / private network / tag               | ✅                                                                                                                                                                                      |
| **ตั้ง rDNS (PTR)**                                  | ❌ **ไม่มีใน API และไม่มีใน terraform provider** ([issue #41](https://github.com/contabo/terraform-provider-contabo/issues/41) ยังเปิดค้าง) → ต้องกดใน **CCP → Reverse DNS Management** |
| **ปลดพอร์ต 25 ถ้าโดนคลุม / ขอย้าย IP ที่ติดบัญชีดำ** | ❌ ต้องเปิดตั๋วซัพพอร์ต                                                                                                                                                                 |

**สรุป:** โครงเครื่องอัตโนมัติได้ทั้งหมด (terraform หรือ curl) แต่ **PTR ต้องกดมือ 1 ครั้ง** ซึ่งเป็น
ขั้นที่ห้ามลืมสำหรับเมลเซิร์ฟเวอร์ — ให้ถือเป็น manual step ในเช็กลิสต์ ไม่ใช่ของที่ automate ได้

> 🔴 **ค่าลับที่ส่งมาในแชท (Client ID `INT-153…` + secret) ถือว่ารั่วแล้ว** — ให้ **หมุนใหม่ใน CCP**
> ก่อนใช้งานจริง แล้วเก็บใน password manager · และค่าที่ให้มายัง **ไม่ครบ** สำหรับขอ token
> (ขาด API user + API password) จึงยังเรียก API ไม่ได้จากตรงนี้

## 4. กับดัก 5 ข้อที่ต้องรู้ก่อนเริ่ม

1. **🔴 MTA-STS อยู่ที่ `mode: enforce` และล็อก `mx: stalwart.perpos.ai` ไว้**
   ถ้าเปลี่ยน MX เป็น `mailserver.perpos.ai` โดยไม่แก้ policy ก่อน → ผู้ส่งที่แคช policy ไว้
   (Gmail/Outlook แคชได้ถึง 24 ชม.) จะ **ปฏิเสธการส่งเข้าเรา** ไม่ใช่แค่เตือน
   ⇒ ต้อง **แก้ policy ให้มี MX ทั้งสองชื่อ + ขยับ `id` ก่อนวันย้ายอย่างน้อย 24 ชม.**
   (หรือลด `max_age` ลงก่อนล่วงหน้า) — ข้อนี้พลาดแล้วเมลเข้าไม่ได้ทั้งระบบ
2. **IP ใหม่ของ Contabo อาจติดบัญชีดำมาก่อน** — ต้องเช็ก **ทันทีที่ได้ IP ก่อนย้ายอะไรทั้งสิ้น**
   (Spamhaus / Barracuda / UCEPROTECT / SpamCop) · ถ้าสกปรก → เปิดตั๋วขอย้าย IP หรือลบเครื่องสร้างใหม่
   _ทำข้อนี้ให้จบก่อนแตะ DNS แม้แต่ระเบียนเดียว_
3. **ใบรับรอง TLS ต้องครอบชื่อใหม่** — Stalwart ใช้ชื่อเดียวกันทั้ง MX/IMAP/JMAP/หน้า OAuth
   ⇒ ออกใบใหม่ที่มี `mailserver.perpos.ai` + `login.perpos.ai` (+ ชื่อเดิมช่วง dual-run)
4. **ย้ายข้อมูลเมล = ย้ายทั้งไดเรกทอรีของ Stalwart** (เมลเก็บบนดิสก์เครื่อง ไม่มี object storage)
   ⇒ ต้อง **หยุดบริการก่อน rsync รอบสุดท้าย** ไม่งั้นดัชนีไม่ตรงกับ blob
5. **Contabo จำกัด ~25 ฉบับ/นาที** และคลุมพอร์ต 25 ได้ถ้ามีรายงาน abuse
   ⇒ เพียงพอกับปริมาณของเรา แต่ **ห้ามเอาเครื่องนี้ไปรันงานอื่นที่ยิงเมล** และไม่ควรรวมงานทดลอง
   ไว้เครื่องเดียวกับเมล (เครื่องเมลต้องน่าเบื่อที่สุดในระบบ)

## 8. Rollback

จนกว่าจะลบเครื่องเก่า (D+7) การถอยคือ **ชี้ MX/A กลับไป `stalwart.perpos.ai` + เปิดบริการเครื่องเก่า**
— ทำได้ภายในเวลา TTL (5 นาที) เพราะ:

- ชื่อเดิมยังอยู่ใน MTA-STS policy ตลอดช่วง dual-run (จึงไม่ถูก enforce ปฏิเสธ)
- IP เดิมยังอยู่ใน SPF
- เมลที่เข้าเครื่องใหม่ไปแล้วจะ **ไม่ย้อนกลับเอง** → ต้อง rsync ย้อนทิศก่อนเปิดเครื่องเก่ารับงานต่อ

**เงื่อนไขที่ถือว่าต้องถอย:** เมลเข้าไม่ได้เกิน 15 นาที · TLS ใช้ไม่ได้ · webmail login ไม่ผ่าน

## 10. ตัดสินแล้ว

- **ไม่ใช้ terraform** — เครื่องเดียว ไม่ต้องมี state ให้ดูแล · สร้างด้วย `curl` เรียก API + cloud-init
- **คง `login.perpos.ai` ไว้เป็น alias** — ผู้ใช้เห็นชื่อเดิมตอนกรอกรหัสผ่าน และ **ไม่ต้องแตะ `MAIL_OAUTH_ISSUER`**
  ⇒ ต้องย้าย A/AAAA ของ `login` ไปเครื่องใหม่ และใบรับรองต้องครอบ `login.perpos.ai` ด้วยเสมอ
- **ขาออก = ส่งตรงพอร์ต 25 จากเครื่องเราเอง** (ตัดสินโดยเจ้าของระบบ 2026-08-18 · เดิมร่างไว้ว่าใช้ relay)
  ⇒ **พอร์ต 25 กลายเป็นข้อกำหนด ไม่ใช่ทางเลือก** และชื่อเสียงของ IP กลายเป็นเกณฑ์อันดับหนึ่งของการเลือกผู้ให้บริการ
  ⇒ สิ่งที่ต้องทำเพิ่มอยู่ใน §12 · ข้อควรระวังที่เคยแย้งไว้ (ปริมาณน้อย = ไม่มีเครดิตสะสม) ยังจริงอยู่
  แต่ยอมรับความเสี่ยงนั้นแล้ว — จึงต้องชดเชยด้วยการเฝ้าบัญชีดำและมี fallback (§12)

## 11. เปรียบเทียบ ย้าย vs ไม่ย้าย (ตัดค่าแรงและความเสี่ยงเมลล่มชั่วคราวออก)

> เงื่อนไข: ทราฟฟิกบางมาก · เมลไม่ใช่ช่องทางหลัก · ความน่าเชื่อถือ = "มีอีเมลองค์กร" เท่านั้น

### ข้อสังเกตที่พลิกการตัดสิน

**IP ของเครื่องมีผลกับ "ขาออก" เท่านั้น — ขาเข้าไม่สนใจชื่อเสียง IP ของเรา**
ดังนั้นถ้าขาออกยังผ่าน relay เครื่องนี้ก็เหลือหน้าที่ **รับเมล + เก็บ + เสิร์ฟ IMAP/JMAP** ล้วน ๆ
⇒ **จุดอ่อนหลักของ Contabo (ชื่อเสียง IP + พอร์ต 25 ถูกคลุมได้) ใช้ไม่ได้กับเราเลย**

**ปริมาณน้อยเป็นเหตุผล _ค้าน_ การส่งเอง ไม่ใช่สนับสนุน**
ชื่อเสียง IP สร้างจากปริมาณที่สม่ำเสมอ · IP ที่แทบไม่ส่งอะไรเลยไม่มีเครดิตสะสม
โดนกรองเข้า junk ง่ายกว่า และถ้าติดบัญชีดำก็ไม่มีวอลุ่มให้ฟื้นตัว
⇒ ที่ปริมาณของเรา **"เช่าชื่อเสียง" จาก relay ได้ deliverability ดีกว่าเสมอ**

## 12. ส่งตรงพอร์ต 25 — สิ่งที่ต้องมีครบก่อนเปิดใช้

> ตัดสินแล้วว่าขาออกไม่ผ่าน relay ⇒ **เราเป็นเจ้าของชื่อเสียงเองทั้งหมด** ไม่มีใครรับแทน

| ต้องมี                                 | สถานะ/สิ่งที่ต้องทำ                                                                                                                                                  |
| -------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| PTR ตรงกับ HELO ทั้ง v4 + v6           | ตั้งมือใน CCP (§2) — **ไม่ตรง = โดนปฏิเสธตั้งแต่ทักทาย**                                                                                                             |
| DKIM เซ็นเอง                           | ให้ Stalwart เซ็น (เลิกพึ่ง selector `brevo2`) · ประกาศ DNS ทุกโดเมน                                                                                                 |
| SPF                                    | ตัด `include:spf.brevo.com` ออกหลังเลิก relay เหลือ `ip4`/`ip6` ของเครื่องใหม่                                                                                       |
| DMARC                                  | ตอนนี้ `p=none` → เลื่อนเป็น `quarantine` หลังส่งเองนิ่งแล้ว                                                                                                         |
| MTA-STS / TLS-RPT                      | มีแล้ว (ระวังกับดัก §4.1 ตอนเปลี่ยนชื่อ)                                                                                                                             |
| **Feedback loop**                      | สมัคร **Google Postmaster Tools** + **Microsoft SNDS/JMRP** — ไม่มีตัวนี้ = ตาบอด ไม่รู้ว่าโดนตีตกเมื่อไร                                                            |
| `abuse@` / `postmaster@` รับเมลได้จริง | บังคับ — blocklist ทุกเจ้าติดต่อทางนี้                                                                                                                               |
| **เฝ้าบัญชีดำอัตโนมัติ**               | ผูกเข้า [`server-monitor.ts`](../apps/perpos/src/lib/mail/server-monitor.ts) ให้ตรวจ DNSBL ทุกวัน แล้วเตือน LINE — ติดแล้วต้องรู้ภายในวันเดียว ไม่ใช่รู้ตอนลูกค้าบ่น |
| **เส้นทางสำรอง**                       | ตั้ง Stalwart ให้ **fallback ไป relay 587** เมื่อส่งตรงไม่สำเร็จ — ได้อิสระเต็มที่โดยไม่แลกกับ "ส่งไม่ออกเลย" ถ้าวันหนึ่ง IP ติดบัญชีดำ                              |

**ข้อจำกัดที่ต้องยอมรับ:** ปริมาณของเราน้อย ⇒ IP แทบไม่มีเครดิตสะสม ⇒ โอกาสตกถังขยะสูงกว่า relay
และถ้าติดบัญชีดำจะไม่มีวอลุ่มช่วยให้ฟื้นตัวเอง ต้องเดินเรื่องขอปลดเองทุกครั้ง

2. ย้าย `SystemSettings.defaultCertificateId` ไปใบอื่นชั่วคราว → `x:Certificate/set destroy`
3. ลบ `x:Task` AcmeRenewal ที่ค้างของโดเมนนั้น → สลับ `certificateManagement` เป็น `Manual` แล้วกลับเป็น `Automatic` → `ReloadSettings`
4. ใบใหม่มาภายใน ~1 นาที → ตั้ง `defaultCertificateId` กลับ → `ReloadTlsCertificates`

> ⚠️ ระหว่างขั้น 2–4 **ไม่มีใบรับรองของโดเมนนั้น** และ JMAP ผ่าน `https://stalwart.perpos.ai` จะเรียกไม่ได้ (ใบไม่ตรงชื่อ)
> → ใช้ `ssh` แล้วยิงไป `http://localhost:8080/jmap/` แทน
