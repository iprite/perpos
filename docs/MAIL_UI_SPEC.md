# สเปก UI/UX — โมดูลอีเมล (webmail + หลังบ้าน)

> คู่กับ [`docs/MAIL_SERVER_PLAN.md`](MAIL_SERVER_PLAN.md) (สถาปัตยกรรม) · เอกสารนี้ = **หน้าตาและการใช้งาน**
> อยู่ใต้ [`DESIGN.md`](../DESIGN.md) เสมอ — เอกสารนี้ **ไม่ยกเลิกกฎใด** แค่เติมส่วนที่ DESIGN.md ยังไม่ครอบคลุม
> (DESIGN.md ออกแบบมาสำหรับหน้า CRUD/ตาราง · **webmail เป็น archetype คนละแบบ**)

---

## 0. หลักการ 4 ข้อ

1. **เนื้อหาต้องได้พื้นที่มากที่สุด** — อีเมลคือสิ่งที่ผู้ใช้จ้องทั้งวัน ทุก pixel ที่เป็น chrome คือ pixel ที่เสียไป
2. **มือไม่ต้องออกจากคีย์บอร์ด** — คนอ่านเมลวันละ 100 ฉบับ การกดเมาส์ 3 ครั้งต่อฉบับ = 300 ครั้ง/วัน
3. **ไม่มีอะไรหายโดยไม่ได้ตั้งใจ** — ร่างต้องเซฟเอง · ลบต้องกู้ได้ · ปิดกล่องเขียนต้องไม่ทำร่างหาย
4. **ลูกค้าตั้ง DNS ถูกตั้งแต่ครั้งแรก** — จุดที่พังบ่อยที่สุดของธุรกิจนี้ ไม่ใช่เรื่องเทคนิค แต่เป็นเรื่อง UX

## 1. ⚠️ 3 จุดที่ webmail ชนกฎ DESIGN.md — และทางออก

### จุดที่ 1: chrome ซ้อน 4 ชั้น → เหลือที่อ่านเมลนิดเดียว

ถ้าเอา webmail ยัดใน `<PageShell>` ตรง ๆ จะได้แบบนี้:

```
sidebar 270px │ breadcrumb
              │ ┌─ PageShell header: "อีเมล" ──────────────┐
              │ │ ┌─ โฟลเดอร์ ─┬─ รายการเมล ─┬─ อ่านเมล ─┐│   ← เหลือที่อ่านจริง ~40%
```

**❌ ทางออกที่ไม่เอา:** หลุดออกจาก shell ไปทำ layout เอง (เสีย org switcher + ไม่เป็นชุดเดียวกับแอป)

**✅ ทางออก: ยุบโฟลเดอร์เข้า sidebar ที่มีอยู่แล้ว → เหลือ 2 pane**

```
sidebar 270px          │ ┌─ รายการเมล ─┬─ อ่านเมล ────────┐
├ อีเมล                │ │  380px      │  ที่เหลือทั้งหมด  │
│  ├ กล่องขาเข้า  (12) │ │             │                  │
│  ├ ดาว               │ │             │                  │
│  ├ ส่งแล้ว           │ │             │                  │
│  ├ ร่าง          (2) │ │             │                  │
│  └ ถังขยะ            │ └─────────────┴──────────────────┘
├ โดเมน                │
└ ตั้งค่า              │
```

- **sidebar ของ PERPOS ทำหน้าที่เป็น left rail ของเมลไปในตัว** (แบบเดียวกับ Gmail) — ไม่มี pane ที่สาม
- โฟลเดอร์ = เมนูย่อยของโมดูล `mail` ใน sidebar เดิม
- ⚠️ **แก้ 2026-08-15: M1 ยังไม่มีตัวเลขยังไม่ได้อ่านใน sidebar** — sidebar ถูกสร้างนอก `<MailWorkspace>`
  การส่ง count เข้าไปต้องแก้ `menu-items.tsx`/context กลาง = diff ใหญ่ในไฟล์ที่ใช้ร่วมทั้งแอป
  → M1 แสดงจำนวนที่หัวรายการของ workspace แทน · **ยกกลับมาทำที่ M3** พร้อมโฟลเดอร์กำหนดเอง
- เมื่อทำแล้ว ตัวเลขยังไม่ได้อ่านใช้ `text-xs font-medium text-gray-500` — **ห้ามใช้ badge สีแดง** (DESIGN.md §14: แดง = ผิดพลาดเท่านั้น)

### จุดที่ 2: `PageShell` มี header + `space-y-6` → กินที่แนวตั้ง

หน้า webmail ใช้ **`<PageShell>` แบบไม่ใส่ `title`** (รองรับอยู่แล้ว — `hasHeader` เป็น false)
แล้วใส่ `width="full"` เพื่อไม่ให้ถูกจำกัดความกว้าง:

```tsx
// ✅ ถูก — ได้ container + padding มาตรฐาน แต่ไม่มี header กินที่
<PageShell width="full">
  <MailWorkspace ... />
</PageShell>
```

หัวข้อ/ปุ่มที่ปกติอยู่ใน PageShell header **ย้ายไปอยู่ในแถบเครื่องมือเหนือรายการเมล** (ดู §2)
— ผู้ใช้รู้อยู่แล้วว่าอยู่หน้าเมล ไม่ต้องมี `<h1>` บอก

### จุดที่ 3: กล่องเขียนเมลควรเป็น modal หรือไม่?

DESIGN.md §13 บังคับ `<Dialog>` สำหรับ popup ทุกตัว แต่กล่องเขียนเมลมีความต้องการพิเศษ:
**คนเขียนเมลมักต้องเปิดเมลอื่นดูระหว่างเขียน**

|            | v1 (ทำเลย)                                                | v2 (ทำเมื่อมีเสียงเรียกร้อง) |
| ---------- | --------------------------------------------------------- | ---------------------------- |
| รูปแบบ     | **`<Dialog size="2xl">` ตามมาตรฐาน**                      | กล่องลอยมุมขวาล่าง (docked)  |
| กันร่างหาย | **เซฟร่างอัตโนมัติทุก 3 วิ** + ปุ่ม "ย่อ" เก็บลงถาดล่างจอ | เหมือนกัน                    |

**ตัดสินใจ: v1 ใช้ `<Dialog>` ตามมาตรฐาน** — อย่าเพิ่งประดิษฐ์ primitive ใหม่
ข้อเสียเรื่อง "เปิดเมลอื่นดูไม่ได้" แก้ได้ 90% ด้วย **เซฟร่างอัตโนมัติ + ปุ่มย่อ**
ถ้าใช้จริงแล้วยังเจ็บ ค่อยทำ `<ComposeDock>` แล้วบันทึกเป็นข้อยกเว้นใน DESIGN.md

## 2. หน้าอ่านเมล — `/mail`

> 📌 **แก้ 2026-08-15 (M1):** webmail อยู่ที่ **top-level `/mail`** ไม่ใช่ `/[orgSlug]/mail` — ตัวตนของ webmail
> คือ **mail account ที่ผ่าน OAuth ของ Stalwart ไม่ผูกกับ org/profile ของ PERPOS**
> (สัญญาเต็ม: [`.claude/feature-factory/specs/mail-webmail-read.md`](../.claude/feature-factory/specs/mail-webmail-read.md))
> · หน้าหลังบ้าน §5 ยังเป็น `/[orgSlug]/mail/*` ต่อ org เหมือนเดิม (M0)

### แถบเครื่องมือ (สูง 48px, sticky)

```
[☑] [🗑] [📁▾] [•อ่านแล้ว]  │  🔍 ค้นหาในเมล        │  [เขียนเมล +]
 ↑ โผล่เมื่อเลือกอย่างน้อย 1 ฉบับ        ↑ ยืดเต็มที่ว่าง      ↑ primary ขวาสุดเสมอ
```

- **ปุ่มจัดการโผล่เมื่อเลือกแล้วเท่านั้น** — ยังไม่เลือกก็ไม่ต้องโชว์ปุ่มที่กดไม่ได้ (ใช้ `<BulkActionBar>` ที่มีอยู่)
- ช่องค้นหาใช้ `<FilterSearch>` · **ห้าม `flex-1` เดี่ยว ๆ** (DESIGN.md §4) → `flex-1 min-w-[12rem] max-w-xl`
- ปุ่ม "เขียนเมล" = `<Button>` primary ขวาสุด ตาม DESIGN.md
- ตัวกรอง (ยังไม่ได้อ่าน / มีไฟล์แนบ / ช่วงวันที่) ซ่อนหลังปุ่มไอคอน `<Filter>` + **จุดเหลืองเมื่อกรองค้าง** (DESIGN.md §4)

### แถวเมลในรายการ — ต้องแน่นกว่าตารางปกติ

> ⚠️ **ห้ามใช้ `<Table>`** สำหรับรายการเมล — `TableCell` เป็น `px-4 py-3` + `whitespace-nowrap`
> ซึ่งออกแบบมาสำหรับข้อมูลตาราง ไม่ใช่รายการที่มี 2 บรรทัดและต้องหนาแน่น
> ใช้ `<ul>/<li>` + primitive ใหม่ `<MailRow>` แทน (ดู §7)

```
┌──────────────────────────────────────────────────────────┐
│ ☐ ●  สมชาย ใจดี                                   14:32  │  ← บรรทัด 1: ผู้ส่ง + เวลา
│      ใบเสนอราคางานติดตั้ง — ส่งไฟล์ตามที่คุยไว้ครับ  📎  │  ← บรรทัด 2: หัวเรื่อง — ตัวอย่าง
└──────────────────────────────────────────────────────────┘
   สูง 64px · hover:bg-gray-50 · แถวที่เปิดอยู่ bg-gray-100
```

| องค์ประกอบ      | ยังไม่ได้อ่าน                        | อ่านแล้ว                            |
| --------------- | ------------------------------------ | ----------------------------------- |
| จุดหน้าแถว      | `●` `bg-primary` (charcoal) 6px      | ไม่มีจุด (เว้นที่ไว้ ไม่ให้แถวขยับ) |
| ชื่อผู้ส่ง      | `font-semibold text-gray-900`        | `font-normal text-gray-700`         |
| หัวเรื่อง       | `font-medium text-gray-900`          | `text-gray-600`                     |
| ตัวอย่างเนื้อหา | `text-gray-500`                      | `text-gray-400`                     |
| เวลา            | `text-xs text-gray-500 tabular-nums` | เหมือนกัน                           |

**กฎแถวเมล:**

- **หัวเรื่อง + ตัวอย่างอยู่บรรทัดเดียวกัน** คั่นด้วย `—` แล้ว `truncate` — ไม่ใช่คนละบรรทัด (ประหยัดที่ 30%)
- **เวลาแสดงแบบสัมพัทธ์แบบไทย**: วันนี้ → `14:32` · เมื่อวาน → `เมื่อวาน` · ปีนี้ → `12 ส.ค.` · ปีก่อน → `12 ส.ค. 67` (พ.ศ. ตาม DESIGN.md §14)
- **เธรด** = แสดงเป็นแถวเดียว + ตัวเลขจำนวนข้อความในวงเล็บ `(3)` ต่อท้ายชื่อผู้ส่ง
- ไอคอนไฟล์แนบ `📎` ชิดขวาบรรทัด 2 · ดาวกดได้ที่หัวแถว
- **ห้ามใส่คอลัมน์ปุ่ม action ในแถว** (DESIGN.md §5 ข้อ 3) — ปุ่มอยู่ในแถบเครื่องมือหลังเลือก หรือใน hover ของแถวได้อย่างมาก 2 ปุ่ม
- **เมลใหม่เข้ามาระหว่างอ่าน ห้ามแทรกจนแถวกระโดด** — ถ้าเลื่อนลงมาแล้ว (`scrollTop > 0`) ให้ขึ้นแถบ
  **"มีเมลใหม่ N ฉบับ"** ค้างที่หัวรายการ กดแล้วค่อยแทรก+เลื่อนขึ้นบนสุด · อยู่บนสุดอยู่แล้วค่อยแทรกได้ทันที
  (แถวที่สายตาจับอยู่กระโดดหนี = คลิกผิดฉบับ)
- **แบ่งหน้าใช้ infinite scroll ไม่ใช่ `<TablePager>`** — นี่คือ**ข้อยกเว้นที่ตั้งใจ**จาก DESIGN.md §5.1
  เพราะเมลเป็น stream ตามเวลา ไม่ใช่ชุดข้อมูลที่คนอยากกระโดดไป "หน้า 7"
  · โหลดทีละ 50 · มีปุ่ม "โหลดเพิ่ม" ให้กดเองด้วยสำหรับคนที่ไม่ชอบ scroll อัตโนมัติ

### บานอ่านเมล (ขวา)

```
หัวเรื่องของเมล                                    [↩ ตอบ] [↪ ส่งต่อ] [🗑]
─────────────────────────────────────────────────────────────────────
(A) สมชาย ใจดี  <somchai@example.com>                    12 ส.ค. 14:32
    ถึง: คุณ                                                    [▾]
─────────────────────────────────────────────────────────────────────

   เนื้อหาเมล ... (max-w-3xl — ห้ามยืดเต็มจอ อ่านยาก)

─────────────────────────────────────────────────────────────────────
📎 ใบเสนอราคา.pdf (240 KB)   [ดู] [ดาวน์โหลด]
```

- **เธรดหลายข้อความ**: กางเฉพาะ**ฉบับล่าสุด** · ฉบับอื่นยุบเป็นหัวข้อบรรทัดเดียว (ผู้ส่ง · เวลา · ตัวอย่าง) กดกางได้
  · เธรดเกิน 5 ฉบับ เลื่อนไปฉบับล่าสุดให้อัตโนมัติตอนเปิด
  · ยุบ/กางด้วย CSS grid (`grid-rows-[0fr]` ⇄ `[1fr]` + `overflow-hidden`) — **ไม่วัดความสูงเนื้อหา**
- **ข้อความที่อ้างถึง (quoted) ถูกยุบให้อัตโนมัติ** เป็นแถบ `แสดงข้อความที่อ้างถึง` กดกางได้
  (ทำที่ฝั่งเซิร์ฟเวอร์ด้วย `<details>` — กางได้โดยไม่ต้องใช้สคริปต์)
- **เนื้อหาจำกัด `max-w-3xl`** — บรรทัดยาวเกิน ~75 ตัวอักษรอ่านยากมาก (แม้จอกว้าง)
- **HTML ของเมลต้อง sanitize + เปิดใน sandbox** — บล็อกรูปจากภายนอกจนกว่าจะกด "แสดงรูป"
  (กันการติดตามว่าเปิดอ่านแล้ว + เป็นด่านความปลอดภัย)
- ปุ่ม `ตอบ` / `ตอบทั้งหมด` / `ส่งต่อ` อยู่ **บนสุด** (คนตัดสินใจตอบตั้งแต่อ่านหัวเรื่อง ไม่ต้องเลื่อนลงไปหา)
- `<Avatar>` ใช้ตัวที่มีอยู่แล้ว (fallback อักษรย่อ)
- **ยังไม่เลือกเมล** → empty state ตาม DESIGN.md §8 (ไอคอน + "เลือกอีเมลเพื่ออ่าน" + ปุ่ม "เขียนเมล")

## 3. ⌨️ คีย์ลัด — สิ่งที่ทำให้ "ใช้ง่าย" จริง

ทำตั้งแต่ M1 **ไม่ใช่ของแถมทีหลัง** · กด `?` เปิดตารางคีย์ลัด

| ปุ่ม      | ทำอะไร           |     | ปุ่ม           | ทำอะไร             |
| --------- | ---------------- | --- | -------------- | ------------------ |
| `j` / `k` | ลง / ขึ้น        |     | `c`            | เขียนเมลใหม่       |
| `Enter`   | เปิดเมล          |     | `r`            | ตอบ                |
| `Esc`     | ปิด / กลับรายการ |     | `a`            | ตอบทั้งหมด         |
| `x`       | เลือก/ไม่เลือก   |     | `f`            | ส่งต่อ             |
| `e`       | เก็บเข้าคลัง     |     | `/`            | ค้นหา              |
| `#`       | ลบ               |     | `g` `i`        | ไปกล่องขาเข้า      |
| `s`       | ติดดาว           |     | `?`            | ตารางคีย์ลัด       |
| `u`       | ทำเป็นยังไม่อ่าน |     | `⌘/Ctrl+Enter` | ส่ง (ในกล่องเขียน) |

- ปิดคีย์ลัดอัตโนมัติเมื่อโฟกัสอยู่ใน input/textarea/contenteditable
- **ตารางคีย์ลัด (`?`) ต้องเรนเดอร์จากรายการเดียวกับที่ผูกปุ่มจริง** — ประกาศเป็นข้อมูลชุดเดียว
  (ไม่งั้นตารางกับของจริงหลุด sync แล้วผู้ใช้เชื่อไม่ได้)
- **แสดงสัญลักษณ์ปุ่มตามระบบปฏิบัติการ**: mac → `⌘ ⇧ ↵ ⌫` · Windows → `Ctrl Shift Enter Backspace`
- `g` `i` เป็น **คีย์ต่อเนื่อง** (กด `g` แล้วตามด้วย `i`) ไม่ใช่กดพร้อมกัน
- **ทุกการกระทำที่ทำลายข้อมูลต้องมี "เลิกทำ"** — ลบ/เก็บเข้าคลังแล้วขึ้น toast `เก็บแล้ว [เลิกทำ]` ค้าง 8 วิ
  → ทำให้กด `e` รัว ๆ ได้โดยไม่กลัว **นี่คือหัวใจของความเร็ว**

## 4. กล่องเขียนเมล

```tsx
<Dialog open={open} onOpenChange={confirmClose}>
  <DialogContent size="2xl">
    <DialogHeader>
      <DialogTitle>เขียนอีเมล</DialogTitle>
    </DialogHeader>
    <form className="flex min-h-0 flex-1 flex-col" onSubmit={send}>
      <DialogBody fixedHeight>
        {" "}
        {/* กล่องไม่เด้งสูง-เตี้ยตอนเพิ่ม cc */}
        …ถึง / สำเนา / หัวเรื่อง / เนื้อหา…
      </DialogBody>
      <DialogFooter>
        <span className="mr-auto text-xs text-gray-400">{savedLabel}</span>
        <Button variant="outline" onClick={minimize}>
          ย่อ
        </Button>
        <Button type="submit">ส่ง</Button>
      </DialogFooter>
    </form>
  </DialogContent>
</Dialog>
```

- **`ถึง` เป็น chip ไม่ใช่ข้อความคั่นคอมมา** — ใช้ `<MultiSelect>` ที่มีอยู่ + autocomplete จาก contacts
- `สำเนา` / `สำเนาลับ` **ซ่อนไว้ก่อน** มีลิงก์เล็ก ๆ ให้กางออก (95% ของเมลไม่ใช้)
- **เซฟร่างอัตโนมัติทุก 3 วิ** → แสดง `✓ บันทึกร่างแล้ว` มุมซ้ายล่าง (`text-xs`, จาง ๆ ตาม DESIGN.md §12 — **ไม่ใช่ toast**)
- **ปิดกล่องทั้งที่มีเนื้อหา → ไม่ถามอะไร แค่เก็บเป็นร่าง + toast `เก็บเป็นร่างแล้ว`** (ไม่ใช่ dialog ยืนยัน — น่ารำคาญและร่างไม่เคยหายอยู่แล้ว)
- ไฟล์แนบใช้ `<FileDropzone multiple>` (DESIGN.md บังคับ) — **ลากไฟล์มาวางที่ไหนก็ได้ในกล่องเขียน**
- ปุ่มส่ง disabled ระหว่างส่ง + ข้อความ `กำลังส่ง…` (DESIGN.md §9)
- **ส่งแล้วขึ้น toast `ส่งแล้ว [เลิกทำ]` ค้าง 8 วิ** แล้วค่อยส่งจริง — กันส่งผิดคน ซึ่งเป็นความผิดพลาดที่แก้ไม่ได้

`กล่องทั้งหมด` · `พื้นที่ใช้ไป` · `ส่งเดือนนี้` · `ตีกลับ 30 วัน` (tone=`warning` ถ้า >2%)

### 5.1 ⭐ ตัวช่วยตั้ง DNS — หน้าที่สำคัญที่สุดของโมดูลนี้

**นี่คือจุดที่ลูกค้าพังบ่อยที่สุดและโทษเรา** ตั้ง DNS ผิด → เมลเข้าถังสแปม → "ระบบคุณห่วย"
ต้องออกแบบให้ **คนที่ไม่รู้จัก DNS เลยทำตามได้**

```
┌─ ตั้งค่า DNS สำหรับ example.com ───────────────────────────┐
│  ●───────●───────○───────○      ยืนยันแล้ว 2 จาก 4         │
│  MX     SPF    DKIM   DMARC                                │
├────────────────────────────────────────────────────────────┤
│ ✅ MX — รับอีเมลเข้า                            ยืนยันแล้ว │
│ ✅ SPF — อนุญาตให้เราส่งแทนคุณ                  ยืนยันแล้ว │
│                                                            │
│ ⏳ DKIM — ลงลายเซ็นดิจิทัลให้อีเมล                รอตรวจสอบ │
│    ┌──────────────────────────────────────────────────┐    │
│    │ ชนิด   CNAME                              [คัดลอก]│    │
│    │ ชื่อ    abc123._domainkey                 [คัดลอก]│    │
│    │ ค่า     abc123.dkim.amazonses.com         [คัดลอก]│    │
│    └──────────────────────────────────────────────────┘    │
│    ℹ️ เอาไปใส่ที่ผู้ให้บริการโดเมนของคุณ                    │
│       [ดูวิธีทำสำหรับ Cloudflare ▾]                        │
├────────────────────────────────────────────────────────────┤
│                          [ตรวจสอบอีกครั้ง]  ตรวจล่าสุด 2 น. │
└────────────────────────────────────────────────────────────┘
```

**กฎของหน้านี้:**

1. **ทีละ record ไม่ใช่กองรวม** — ให้ตารางยาว 7 แถวไปทีเดียวคือวิธีที่ลูกค้าทำผิดแน่นอน
2. **ปุ่มคัดลอกทุกช่อง** ใช้ `<CopyCell>` ที่มีอยู่ (เปลี่ยนไอคอนเป็น ✓ 2 วิ ตาม DESIGN.md §12) — **ห้ามให้พิมพ์ตามเอง**
3. **ตรวจสอบอัตโนมัติทุก 30 วิ** ระหว่างเปิดหน้าอยู่ + ปุ่มตรวจเอง → เห็นผลทันทีที่ตั้งเสร็จ (ไม่ต้องรีเฟรช)
4. **อธิบายว่า record นี้ "มีไว้ทำอะไร" เป็นภาษาคน** — ไม่ใช่ศัพท์เทคนิค
   ✅ "DKIM — ลงลายเซ็นดิจิทัลให้อีเมล ทำให้ปลายทางเชื่อว่าเป็นคุณส่งจริง"
   ❌ "DKIM CNAME record for domain verification"
5. **มีคำแนะนำเฉพาะผู้ให้บริการโดเมน** (Cloudflare / GoDaddy / ไทยเสิร์ฟ) แบบพับเก็บได้
6. **ยังยืนยันไม่ครบ = สร้างกล่องเมลไม่ได้** ปุ่มถูก disable + ข้อความบอกว่าติดตรงไหน
   (ปล่อยผ่าน = ลูกค้าส่งเมลเข้าถังสแปมแล้วโทษเรา)
7. ผิดพลาด → บอก**สิ่งที่เจอจริง** ไม่ใช่แค่ "ไม่ผ่าน":
   `พบค่า "v=spf1 include:_spf.google.com ~all" — ต้องเพิ่ม include:amazonses.com เข้าไปด้วย`

## 6. หน้าหลังบ้านของ **เรา** — `/admin/mail`

super_admin เท่านั้น · guard = `requireSuperAdminPage()` (DESIGN.md/AGENTS.md — **ห้ามใช้ service-role กับข้อมูล per-org**)

| แท็บ (`<SegmentedControl>`) | เนื้อหา                                                                            |
| --------------------------- | ---------------------------------------------------------------------------------- |
| **ภาพรวม**                  | `<StatCard>`: org ที่ใช้อยู่ · กล่องทั้งหมด · พื้นที่รวม · ตีกลับ/ร้องเรียน 24 ชม. |
| **ลูกค้า**                  | ตารางต่อ org: กล่อง / พื้นที่ / ส่งเดือนนี้ / อัตราตีกลับ / สถานะ                  |
| **สุขภาพระบบ**              | คิวค้าง · ดิสก์ · ใบรับรอง TLS เหลือกี่วัน · ผล blacklist                          |
| **เหตุการณ์**               | `mail_events` (bounce/complaint) กรองตาม org ได้                                   |

- **แถวไหนน่าห่วงต้องเห็นทันที** — อัตราตีกลับ >2% = `<StatusBadge tone="warning">` · >5% = `tone="danger"`

- **ดิสก์ >80% ต้องเด้งเป็นแถบเตือนบนสุด** — ดิสก์เต็ม = รับเมลไม่ได้ทุกลูกค้าพร้อมกัน
- ⚠️ **หน้านี้ห้ามมีทางเข้าไปอ่านเนื้อหาเมลของลูกค้าเด็ดขาด** — เห็นได้แค่ metadata
  (ดู §7 ของ MAIL_SERVER_PLAN.md · ถ้าจำเป็นต้องเข้าถึงเพื่อแก้ปัญหา ต้องมี audit log + ลูกค้ายินยอมเป็นครั้ง ๆ)

## 8. มือถือ

หน้าจอแคบ (`< lg`) **ยุบเหลือ pane เดียว**:

- รายการเมลเต็มจอ → แตะเปิด → บานอ่านเมลเลื่อนเข้ามาทับ + ปุ่มย้อนกลับซ้ายบน
- ปุ่ม "เขียนเมล" กลายเป็น **FAB วงกลมมุมขวาล่าง** (นิ้วโป้งเอื้อมถึง)
- แถบเครื่องมือยุบเหลือ ค้นหา + เมนู `⋯`
- **ปัดซ้าย/ขวาบนแถว** = เก็บเข้าคลัง / ลบ (พร้อม "เลิกทำ" เหมือนเดิม)
- **สั่งการด้วยนิ้วต้องแตะได้อย่างน้อย 44×44px** — แถว 64px ผ่านอยู่แล้ว แต่ checkbox/ดาวต้องมี hit area พอ

## 10. ❌ Anti-patterns เฉพาะหน้าเมล

| ห้ามทำ                           | ทำไม                                          | ทำแทนด้วย                             |
| -------------------------------- | --------------------------------------------- | ------------------------------------- |
| ใช้ `<Table>` ทำรายการเมล        | py-3 + nowrap แน่นไม่พอ                       | `<MailList>` + `<MailRow>`            |
| badge สีแดงนับเมลใหม่            | DESIGN.md: แดง = ผิดพลาดเท่านั้น              | ตัวเลข `text-gray-500` + จุด charcoal |
| ยืนยัน "แน่ใจว่าจะลบ?" ทุกครั้ง  | ทำให้ทำงานเร็วไม่ได้                          | ลบทันที + `[เลิกทำ]` 8 วิ             |
| เนื้อหาเมลยืดเต็มจอกว้าง         | บรรทัดยาวเกิน 75 ตัวอักษร อ่านยากมาก          | `max-w-3xl`                           |
| โหลดรูปจากภายนอกอัตโนมัติ        | ถูกติดตามว่าเปิดอ่าน + เสี่ยงความปลอดภัย      | บล็อกไว้ + ปุ่ม "แสดงรูป"             |
| แสดง HTML ของเมลตรง ๆ            | XSS                                           | sanitize + sandboxed iframe           |
| ให้ตั้ง DNS จากตารางยาว 7 แถวรวด | ลูกค้าทำผิดแน่นอน                             | ตัวช่วยทีละขั้น + ตรวจสอบสด (§5.1)    |
| `<TablePager>` ในรายการเมล       | เมลเป็น stream ตามเวลา ไม่มีใครกระโดดไปหน้า 7 | infinite scroll + ปุ่มโหลดเพิ่ม       |
| แอดมินเปิดอ่านเมลลูกค้าได้       | ผิด PDPA + ทำลายความเชื่อใจ                   | เห็นได้แค่ metadata                   |
