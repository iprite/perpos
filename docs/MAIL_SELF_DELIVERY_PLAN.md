## 2. เฟส 2 — ตัวตนต้องแน่นก่อนส่งฉบับแรก

### 2.1 เช็คว่า IP สะอาด (ทำก่อนเสมอ ทั้งตอนปลดพอร์ตและตอนย้ายเครื่อง)

```bash
IP=46.225.14.18
REV=$(echo $IP | awk -F. '{print $4"."$3"."$2"."$1}')
for bl in zen.spamhaus.org b.barracudacentral.org bl.spamcop.net dnsbl.sorbs.net; do
  echo -n "$bl: "; dig +short "$REV.$bl" A | head -1 || true; echo
done
```

ได้ค่าใด ๆ กลับมา = ติดบัญชีดำ ต้องยื่น delist ก่อน (หรือขอ IP อื่น) · ไม่มีผลลัพธ์ = สะอาด

### 2.2 เปลี่ยน DNS 3 อย่างพร้อมกันตอนตัด relay

| record                | ตอนนี้                                   | หลังส่งเอง                                                                  |
| --------------------- | ---------------------------------------- | --------------------------------------------------------------------------- |
| **SPF**               | `… include:spf.brevo.com ~all`           | `v=spf1 ip4:46.225.14.18 ip6:2a01:4f8:c2c:105a::1 ~all`                     |
| **DMARC**             | `p=none; rua=mailto:rua@dmarc.brevo.com` | `p=none; rua=mailto:dmarc@perpos.ai` → ค่อยขยับเป็น `quarantine` → `reject` |
| **MTA-STS / TLS-RPT** | ยังไม่ได้ประกาศเป็นทางการ                | เปิดพร้อม DANE (TLSA มีในโซนไฟล์ของ Stalwart แล้ว)                          |

> 🔴 **จุดแก้โค้ดมีที่เดียว** = [`lib/mail/dns-records.ts`](../apps/perpos/src/lib/mail/dns-records.ts)
> (`MAIL_RELAY_SPF_INCLUDE`, `MAIL_DMARC_RUA`) — แก้ที่นี่แล้วตัวช่วยตั้ง DNS ของลูกค้าทุกโดเมน
> เปลี่ยนตาม + มีเทสคุมใน `dns-records.test.ts` · **ห้ามไปแก้ค่าเป็นราย ๆ ที่หน้าเว็บ**

### 2.3 สลับเส้นทางใน Stalwart

`x:MtaRoute` ที่ชี้ `smtp-relay.brevo.com` → ใช้ route ชนิด `Mx` (ส่งตรงตาม MX ปลายทาง)
· ทำผ่าน `x:MtaOutboundStrategy` ให้ชี้ route ใหม่ (ดู `MAIL_HANDOFF.md` §G — สร้าง route
เฉย ๆ ไม่มีผลถ้าไม่ตั้ง strategy) · **เก็บ route relay เดิมไว้ อย่าลบ** (ดูข้อ 5)

## 3. เฟส 3 — warm-up + สมัคร postmaster

- **warm-up**: เริ่มวันละหลักสิบฉบับ เพิ่มประมาณเท่าตัวทุก 2–3 วัน ให้ถึงเพดานจริงใน ~3 สัปดาห์
  · ช่วงแรกส่งไปยังปลายทางที่ "มีคนเปิดจริง" (ลูกค้าที่คุยกันอยู่) ไม่ใช่ยิงรวดไปที่อยู่ที่ไม่เคยติดต่อ
- **สมัคร 3 ที่ — นี่คือ "ตาที่มองเห็นชื่อเสียงตัวเอง" ที่ relay เคยทำแทนเรา**
  1. **Google Postmaster Tools** (ยืนยันโดเมนด้วย TXT) — เห็น spam rate/reputation ของ Gmail
  2. **Microsoft SNDS + JMRP** — SNDS = สถิติ IP ฝั่ง Outlook · JMRP = feedback loop เวลาคนกด "ขยะ"
  3. **Yahoo Complaint Feedback Loop**
- เกณฑ์ที่ต้องเฝ้า: **spam rate ของ Gmail ต้องต่ำกว่า 0.10%** (เกิน 0.30% = เริ่มถูกตีเป็นสแปมทั้งโดเมน)

## 4. เฟส 4 — ของที่ relay เคยทำให้ ต้องทำเอง

1. **bounce / complaint → รายชื่อระงับส่งอัตโนมัติ**
   - hard bounce (5xx) = หยุดส่งที่อยู่นั้นถาวรจนกว่าคนจะปลด · complaint = หยุดทันที
   - เก็บลงตาราง **`mail_events`** (สเปกวางไว้ใน `MAIL_UI_SPEC.md` §6 แต่ยังไม่ได้สร้าง)
   - ⚠️ ส่งซ้ำเข้าที่อยู่ที่ตีกลับถาวรคือพฤติกรรมที่ทำให้ IP เสียชื่อเร็วที่สุด
2. **อ่าน DMARC aggregate + TLS-RPT เอง** (ตอนนี้ Brevo เป็นคนอ่าน) — เข้ากล่อง `dmarc@perpos.ai`
   แล้วแปลงเป็นสรุปในแท็บ "สุขภาพระบบ"
3. **เฝ้าบัญชีดำรายวัน** — สคริปต์ในข้อ 2.1 รันเป็น cron แล้วเตือนเมื่อขึ้นบัญชี
4. **ต่อเข้าหน้าที่มีอยู่แล้ว**: คิวค้าง + ใบรับรอง TLS อยู่ในแท็บสุขภาพระบบของ `/admin/mail` แล้ว
   — เพิ่มการ์ด "อัตราตีกลับ 24 ชม." กับ "สถานะบัญชีดำ" ต่อจากนั้น

## 5. สิ่งที่ **ห้าม** ทำ

- ❌ **อย่าตัด relay ทิ้ง 100%** — เก็บไว้เป็นเส้นทางสำรองที่ปิดอยู่ (ไม่ต้องเป็น Brevo/SES;
  smtp2go / Postmark / Mailgun EU ก็ได้) เปิดใช้เฉพาะตอน IP หลักโดนบล็อกชั่วคราว
  · ไม่มีทางถอย = วันที่โดนบล็อก เมลลูกค้าค้างทั้งวันโดยเราทำอะไรไม่ได้เลย
- ❌ **อย่าเริ่มส่งเองก่อน DMARC `rua` เป็นของเรา** — จะไม่รู้เลยว่าปลายทางปฏิเสธเพราะอะไร
- ❌ **อย่าตั้ง DMARC `p=reject` ตั้งแต่วันแรก** — ต้อง `none` → ดูรายงาน 2 สัปดาห์ → `quarantine` → `reject`
- ❌ **อย่าส่งเมลของลูกค้าใหม่ทันทีที่ปลดพอร์ตได้** — ยังไม่ warm-up = ยิงเข้าถังสแปมพร้อมกันทั้งโดเมน
