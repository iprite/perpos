# แผนเมลขาออก — ฉบับ "ใช้ภายใน" (2026-08-17)

> 🔄 **เปลี่ยนทิศทาง 2026-08-17: PERPOS Mail ไม่ใช่ผลิตภัณฑ์ขายอีกต่อไป**
> ใช้ภายในบริษัท + **exworker** เป็นหลัก · จุดประสงค์คือ **ความน่าเชื่อถือของตัวแทน**
> (มีอีเมลองค์กรใช้) ไม่ใช่การขายกล่องเมล · โควตา **200 MB/คน** · ทราฟฟิกน้อย
> · เกณฑ์ตัดสินใจใหม่ = **ต้นทุนต่ำที่สุด** ไม่ใช่ SLA ระดับผลิตภัณฑ์
>
> **สิ่งที่ตัดทิ้งจากแผนเดิมทันที** (ไม่ต้องทำแล้ว):
> ย้ายโฮสต์มาไทย (฿1,200–1,400/เดือน) · หน้าหลังบ้านลูกค้า `/[orgSlug]/mail/*` (M0)
> · ยืนยันโดเมนลูกค้าทีละราย · warm-up ยาว + suppression list ระดับผลิตภัณฑ์
>
> **สิ่งที่ยังจริงและใช้ต่อ**: ข้อมูล DNSBL/Barracuda ข้างล่าง · ค่า DNS ที่ต้องตั้ง · ขั้นตอนปลดพอร์ต 25

## 🔴 ปัญหาที่ขัดกับเป้าหมายโดยตรง: relay ฟรีของ Brevo แปะโลโก้

เป้าหมายใหม่คือ **ความน่าเชื่อถือ** แต่ relay ที่ใช้อยู่ (Brevo แผนฟรี) **แปะโลโก้ Brevo ท้ายเมลทุกฉบับ**
จนกว่าจะอัปเกรด ⇒ ตัวแทนส่งเมลหาลูกค้าแล้วมีโลโก้เจ้าอื่นห้อยท้าย = ได้ผลตรงข้ามกับที่ตั้งใจ

| ทางเลือกขาออก                    | เพดาน                               | โลโก้        | ค่าใช้จ่าย |
| -------------------------------- | ----------------------------------- | ------------ | ---------- |
| Brevo ฟรี (ใช้อยู่)              | 300/วัน                             | **แปะโลโก้** | ฟรี        |
| Mailjet ฟรี                      | 200/วัน · 6,000/เดือน               | **แปะโลโก้** | ฟรี        |
| **Resend ฟรี**                   | 100/วัน · 3,000/เดือน · **1 โดเมน** | ไม่แปะ       | ฟรี        |
| **ส่งเองหลังปลดพอร์ต 25 (ก.ย.)** | **ไม่จำกัด · กี่โดเมนก็ได้**        | ไม่แปะ       | **฿0**     |

**ทางที่ควรเดิน**: ก.ย. ยื่นปลดพอร์ต 25 (ฟรี) + ยื่นปลด Barracuda (ฟรี) → **ส่งเองทั้งหมด**
เพราะเรามี 2 โดเมนขึ้นไป (perpos.ai + exworker) ซึ่งชน "1 โดเมน" ของ Resend ฟรีอยู่แล้ว
· ระหว่างรอ ถ้าโลโก้ Brevo รับไม่ได้ ให้ย้ายโดเมนหลักไป Resend ฟรีก่อนชั่วคราว
· **เก็บ relay ไว้เป็นทางสำรองเสมอ** (ปิดไว้ เปิดเมื่อ IP มีปัญหา)

**Barracuda ยังต้องดูแล** — แต่เดิมพันต่างจากตอนเป็นผลิตภัณฑ์: เมลไม่ถึงปลายทางบางองค์กร
= เรื่องน่ารำคาญภายใน ไม่ใช่ลูกค้าที่จ่ายเงินเสียหาย ⇒ **ลองยื่นปลด ถ้าไม่ผ่านก็ยังอยู่กับ relay ได้**
ไม่ต้องย้ายโฮสต์เพราะเหตุนี้อีกต่อไป

### 2.1 เช็คว่า IP สะอาด (ทำก่อนเสมอ ทั้งตอนปลดพอร์ตและตอนย้ายเครื่อง)

```bash
IP=46.225.14.18
REV=$(echo $IP | awk -F. '{print $4"."$3"."$2"."$1}')
for bl in zen.spamhaus.org b.barracudacentral.org bl.spamcop.net dnsbl.sorbs.net; do
  echo -n "$bl: "; dig +short "$REV.$bl" A | head -1 || true; echo

```

ได้ค่าใด ๆ กลับมา = ติดบัญชีดำ ต้องยื่น delist ก่อน (หรือขอ IP อื่น) · ไม่มีผลลัพธ์ = สะอาด

## 3. เฟส 3 — warm-up + สมัคร postmaster

> 📉 **ฉบับใช้ภายใน: ทำแบบย่อพอ** — ปริมาณระดับหลักสิบฉบับ/วัน ไม่ต้อง warm-up เป็นสัปดาห์
> แค่ **อย่ายิงรวดวันแรก** + สมัคร Google Postmaster Tools ไว้ดู spam rate ก็พอ
> (SNDS/JMRP ค่อยทำถ้าเริ่มส่งหา Outlook เยอะ)

- **warm-up**: เริ่มวันละหลักสิบฉบับ เพิ่มประมาณเท่าตัวทุก 2–3 วัน ให้ถึงเพดานจริงใน ~3 สัปดาห์
  · ช่วงแรกส่งไปยังปลายทางที่ "มีคนเปิดจริง" (ลูกค้าที่คุยกันอยู่) ไม่ใช่ยิงรวดไปที่อยู่ที่ไม่เคยติดต่อ
- **สมัคร 3 ที่ — นี่คือ "ตาที่มองเห็นชื่อเสียงตัวเอง" ที่ relay เคยทำแทนเรา**
  1. **Google Postmaster Tools** (ยืนยันโดเมนด้วย TXT) — เห็น spam rate/reputation ของ Gmail
  2. **Microsoft SNDS + JMRP** — SNDS = สถิติ IP ฝั่ง Outlook · JMRP = feedback loop เวลาคนกด "ขยะ"
  3. **Yahoo Complaint Feedback Loop**
- เกณฑ์ที่ต้องเฝ้า: **spam rate ของ Gmail ต้องต่ำกว่า 0.10%** (เกิน 0.30% = เริ่มถูกตีเป็นสแปมทั้งโดเมน)

   - hard bounce (5xx) = หยุดส่งที่อยู่นั้นถาวรจนกว่าคนจะปลด · complaint = หยุดทันที

   - ⚠️ ส่งซ้ำเข้าที่อยู่ที่ตีกลับถาวรคือพฤติกรรมที่ทำให้ IP เสียชื่อเร็วที่สุด
2. **อ่าน DMARC aggregate + TLS-RPT เอง** (ตอนนี้ Brevo เป็นคนอ่าน) — เข้ากล่อง `dmarc@perpos.ai`
   แล้วแปลงเป็นสรุปในแท็บ "สุขภาพระบบ"
3. **เฝ้าบัญชีดำรายวัน** — สคริปต์ในข้อ 2.1 รันเป็น cron แล้วเตือนเมื่อขึ้นบัญชี
4. **ต่อเข้าหน้าที่มีอยู่แล้ว**: คิวค้าง + ใบรับรอง TLS อยู่ในแท็บสุขภาพระบบของ `/admin/mail` แล้ว
   — เพิ่มการ์ด "อัตราตีกลับ 24 ชม." กับ "สถานะบัญชีดำ" ต่อจากนั้น

## 5. สิ่งที่ **ห้าม** ทำ

- ❌ **อย่าตัด relay ทิ้ง 100%** — เก็บไว้เป็นเส้นทางสำรองที่ปิดอยู่ (ไม่ต้องเป็น Brevo/SES;
  smtp2go / Postmark / Mailgun EU ก็ได้) เปิดใช้เฉพาะตอน IP หลักโดนบล็อกชั่วคราว
  · ไม่มีทางถอย = วันที่โดนบล็อก เมลลูกค้าค้างทั้งวันโดยเราทำอะไรไม่ได้เลย
- ❌ **อย่าเริ่มส่งเองก่อน DMARC `rua` เป็นของเรา** — จะไม่รู้เลยว่าปลายทางปฏิเสธเพราะอะไร
- ❌ **อย่าตั้ง DMARC `p=reject` ตั้งแต่วันแรก** — ต้อง `none` → ดูรายงาน 2 สัปดาห์ → `quarantine` → `reject`
- ❌ **อย่าส่งเมลของลูกค้าใหม่ทันทีที่ปลดพอร์ตได้** — ยังไม่ warm-up = ยิงเข้าถังสแปมพร้อมกันทั้งโดเมน

## 7. บันทึกการย้าย exworker.co.th (ทำจริงเสร็จแล้ว 2026-08-17)

เมลของ `exworker.co.th` ย้ายจาก **Bangmod (DirectAdmin, 103.27.200.126)** มาที่ Stalwart ของเรา
· เมลออกใช้ **Resend** (โดเมน verified อยู่ก่อนแล้ว โซน ap-northeast-1)

| ส่วน          | ผลลัพธ์                                                                                                                    |
| ------------- | -------------------------------------------------------------------------------------------------------------------------- |
| กล่องเมล      | 8 กล่อง (7 เดิม + `dmarc@`) · โควตา 200 MB ยกเว้น `admin@` 2 GB · `preawnapa@`/`somjai@` 500 MB                            |
| เมลเก่า       | ย้ายด้วย `imapsync` **1,157 ฉบับ ~957 MB** · รอบสอง skipped ทั้งหมด = ไม่มีตกหล่น                                          |
| ที่ย้ายไม่ได้ | ร่าง 79 MB ใน `kusuma@Drafts` — เกินเพดานคำขอ 50 MB ของ Stalwart (**ตั้งใจปล่อยไว้** ยังอยู่ที่ Bangmod)                   |
| MX            | `10 stalwart.perpos.ai` (TTL 300 · ค่าเดิมเก็บใน `mx-rollback.json`)                                                       |
| ขาออก         | route `resend` → `smtp.resend.com:587` ผูกด้วยเงื่อนไข `sender_domain == 'exworker.co.th'` · **perpos.ai ยังออกทาง brevo** |

**บทเรียนที่ต้องจำ (เจอจริงทั้งสามข้อ)**

1. **`ReloadSettings` หลังแก้ config เสมอ** — ไม่งั้น route ใหม่ไม่มีผลและไม่มีสัญญาณเตือนใด ๆ (ดู `MAIL_HANDOFF.md` §G)
2. **แก้ DNS ต้องกรองด้วย `name` เสมอ ไม่ใช่แค่ `type`** — สคริปต์ที่ดึง "MX ทั้งโซน" แล้วเขียนทับ
   เกือบลบ MX ของ Resend ที่ `send.exworker.co.th` (ใช้รับ bounce) · และตอนแก้ SPF เกือบทับ
   `google-site-verification` เพราะเทียบ `startsWith("v=spf1")` ไม่ผ่าน (Cloudflare เก็บ TXT เก่าพร้อมเครื่องหมายคำพูด)
3. **โควตาต้องดูจากที่ใช้จริง ไม่ใช่ค่ามาตรฐาน** — `somjai@` ใช้ 182 MB จาก 200 MB (เต็ม 91%) และ
   `preawnapa@` ใช้ 217 MB เกินโควตาเดิม 200 MB อยู่แล้วตั้งแต่ก่อนย้าย

**ยังไม่ปิด Bangmod** — เก็บไว้อย่างน้อย 1 สัปดาห์เผื่อย้อนกลับ (MX TTL 300 วิ กลับได้ใน 5 นาที)
